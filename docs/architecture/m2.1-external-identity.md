# M2.1 External identity – design

_Roles: Architect, Engineer, DBA, Security, QA. Stories: [phase-2.md](../requirements/phase-2.md) E2.1. ADRs: 003, 006, 007. Date: 2026-10-19._

## 1. Module layout

External identity lives in `forge.iam` (users, sessions) and `forge.tenancy` (mappings, memberships). `iam` never touches tenancy tables: it calls `tenancy.service.GroupMappings`.

| File | Owns |
| --- | --- |
| `iam/directory.py` | LDAP/AD client (ldap3, blocking, run with `asyncio.to_thread`): search with the service account, bind as the user, groups, disabled accounts, all-users for sync |
| `iam/oidc.py` | Discovery, Authorization Code + PKCE, ID token verification (joserfc), claims → identity |
| `iam/providers.py` | `IdentityProviders`: CRUD, encrypted secret, test, public list |
| `iam/external.py` | `ExternalAuth`: LDAP login, OIDC start/callback, user provisioning, mapping application, group sync |
| `tenancy/mappings.py` | `GroupMappings`: mapping CRUD and `apply` (desired memberships from groups) |
| `api/routes_idp.py` | Public sign-in endpoints and the Admin Console API |

## 2. Data model (migration `0010_external_identity`)

- `identity_provider(id, kind ldap|oidc, name, enabled, position, config jsonb, secret_id, last_sync*)`. The configuration holds no secret; the bind password or client secret is a platform `secret` row (AES-256-GCM envelope, ADR-006), written through `forge_admin` because platform secrets have `project_id IS NULL`.
- `app_user` gains `provider_id`, `external_id` (DN or `sub`; unique per provider) and `external_groups`.
- `membership.source` (`manual` | `mapped`).
- `group_mapping(provider_id, project_id, role_name_id, external_group)` with project RLS like every project table; managed by the Super Admin as `forge_admin`.

## 3. Flows

**LDAP login.** `AuthService.login` tries a local user first. If the login is not an eligible local account (unknown, disabled, not `local`, or local login is off for non-Super-Admins) it spends the same hash cost and tries each enabled LDAP provider in order. A provider search returns exactly one entry (none or several: refuse), then a bind as that DN checks the password; an empty password is refused before any connection because LDAP treats it as an anonymous bind. Directory errors are logged and the next provider is tried; the caller always gets the same `invalid_credentials`. Failures are counted per login across providers in Valkey (`extfail:<login>`, lockout policy thresholds) so Forge does not relay a brute force to the directory.

**OIDC login.** `GET /auth/oidc/{id}/start` stores `state`, `nonce` and the PKCE verifier in Valkey for 10 minutes and redirects. `GET /auth/oidc/callback` takes the state once (`GETDEL`), exchanges the code with the client secret and verifier, and verifies signature (provider JWKS, asymmetric algorithms only), issuer, audience, expiry, subject and nonce. Any failure redirects to `/login?error=oidc_failed` and writes `auth.oidc_failed`.

**Provisioning.** The user is found by `(provider, external_id)`. A new user is created only if neither the email nor the username belongs to another account; otherwise login is refused and `auth.external_conflict` is audited (no merge, so a directory or IdP entry cannot take over a local account). Directory users have no password, no TOTP, and still go through the EULA step. Disabled users stay disabled.

**Mapping.** At every login and sync, `GroupMappings.apply` computes for each project the Role Name of the highest-ranked Role Type among the mappings whose group the user holds (case-insensitive, DN or short name for LDAP), then creates, updates or deletes `mapped` memberships. `manual` memberships are never touched, and a manual membership wins over a mapping. An inactive Role Name or archived project is skipped.

**Sync.** `ExternalAuth.sync` reads every directory user, applies mappings, and disables users that are gone or disabled (sessions revoked, mapped memberships dropped). The API process runs `sync_due` every minute under a Valkey lock, honouring each provider's interval.

**Local login switch.** `auth.local_login.enabled = false` blocks non-Super-Admin local logins; it cannot be set while no provider is enabled, and the last provider cannot be disabled while it is off.

## 4. Choices to confirm with the PO

1. A directory entry whose email or username matches an existing account is refused, not merged. Merging by email is convenient but lets whoever controls a directory attribute take over an account.
2. The LDAP default user filter works on Active Directory and OpenLDAP-style schemas alike only if the attributes exist; the screen exposes the filter and attribute names, and an *Active Directory* flag adds `userAccountControl`.
3. Users without a mapped group sign in and see an empty project list (no self-service access request yet).
4. LDAP connections do not use the outbound HTTP proxy (it is not an HTTP protocol); `FORGE_EXTRA_CA_FILE` and the provider's own CA field cover TLS inspection.
5. OIDC "groups overage" (Entra, more than 200 groups) is not resolved through Graph; such users get no mapped group and the log says so.

## 5. Threat-model delta (TB4)

| STRIDE | Threat | Control |
| --- | --- | --- |
| S | Login via LDAP with an empty password (anonymous bind) | Refused before connecting; test |
| T | LDAP filter injection through the login | RFC 4515 escaping of login and DN; tests with hostile logins |
| S | Account takeover by a directory/IdP entry with a known email | No merge; conflict audited; test |
| S | OIDC code injection, replay, mix-up | `state` single use with TTL, `nonce`, PKCE S256, issuer/audience/signature checks, discovery issuer must equal the configured one; tests with bad nonce, audience, expiry, key, issuer, replayed state |
| I | Bind password or client secret leaks | Encrypted at rest, never returned by the API, redacted in audit; test |
| D | Forge used to brute-force the directory | Per-login failure counter across providers, IP rate limit |
| D | Broken directory locks everyone out | Super Admins keep local login; local login cannot be turned off without a provider |
| E | Stale access after a group change | Mappings re-evaluated on every login and sync; removal ends access on the next request |
