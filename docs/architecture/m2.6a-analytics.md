# M2.6 slice a – Analytics and activity log (design)

_Roles: Architect, Engineer, QA. Stories: spec F7.3, "Activity" (Part 2), US-1.4.2. Epics: E2.12, E2.14. Date: 2026-10-21._

M2.6 is split: **a** (this file) dashboards, Model Insights, activity log; **b** scheduled RAG sources (E2.13), not started.

## 1. Principle
No new tables and no new write path. Every figure is a read-only query over records the platform already keeps (`llm_call`, `guardrail_event`, `use_case_run`, `agent_run`, `audit_event`), so the dashboards cannot drift from the per-run totals (AC9). Code: `backend/src/forge/analytics/service.py`.

## 2. API
| Route | Who | Returns |
| --- | --- | --- |
| `GET /projects/{id}/analytics?since&until` | `project.manage` | totals, series, by model, by user/key, by endpoint, error codes, guardrail summary, adoption, reconciliation |
| `GET /projects/{id}/activity?since&q&limit` | `project.manage` | admin actions, use case runs and agent runs, newest first |
| `GET /admin/model-insights?since&until` | Super Admin | every model across projects, providers, top projects, models with no calls |
| `GET /me/activity?days&limit` | any signed-in user | own runs across projects (home page, default 15 days) |

- Range: default 7 days, at most 180; buckets are hourly up to 3 days, daily above.
- Percentiles (p50, p95 latency; p50, p95 TTFT) are exact (`percentile_cont`) over the period.
- Project queries run in `project_scope` (RLS); Model Insights and `/me/activity` use `admin_scope` and are the only cross-project reads, the second one filtered by the caller's id.

## 3. UI
- **Analytics** menu entry (Project Admins): tiles, calls and cost over time (errors drawn inside the bars), by model, top users, error codes, guardrail interventions, adoption, reconciliation, and the activity log with search and 24 h / 7 d / 180 d filters.
- **Super Admin console → Model Insights**.
- **Home → Recent activity**: 4 tiles and *View All* from the last 15 days (US-1.4.2).
- Charts are a small dependency-free component (`shared/bar-chart.ts`): no chart library to ship, license or vendor for air-gapped installs.

## 4. AC9
The reconciliation box compares the sum of finished agent runs (cost, tokens) with the `llm_call` rows their steps point at (`run_step.llm_call_id`). Use case runs are not added because their totals already contain their agent runs. Test: `tests/integration/test_analytics.py`.

## 5. Choices to confirm with the PO
1. **Retention is configurable, default 180 days** (PO 2026-10-21): setting `activity.retention` (`days`, 1–3650) in the Super Admin settings. It is a read window for the activity log, dashboards and the maximum range; nothing is deleted (`audit_event` is append-only, runs and `llm_call` are kept). A purge job would need a separate decision.
2. **Activity log = admin actions + runs.** Reads of data and logins are not included.
3. **Dashboards are Project Admin only** (`project.manage`). Builders and end users see no cost figures.
4. **Cost is the gateway's estimate** from the model price in the registry (`cost_input`/`cost_output`); cached calls cost 0.
5. **Success means `status = 'ok'`**: rejected calls (quota, validation, guardrail input block) count as errors.
6. **No per-user breakdown for end users of use cases beyond "active users"**; API keys appear under their owner.
7. **Charts are simple bars**, no zoom or export (CSV export not built).

## 6. Not built
CSV/PDF export of dashboards, alerts on thresholds, per-use-case cost (run steps are summed in the run view, not on the dashboard), Langfuse-side views.
