# M3.1 Helm chart and air-gapped bundle – design

_Roles: Architect, Engineer, DevOps. Stories: [phase-3.md](../requirements/phase-3.md) E3.1. Date: 2026-10-22._

## 1. What it is
`deploy/helm/forge` ([README](../../deploy/helm/forge/README.md)) is the Compose stack as a chart. Same images, same environment names, same security posture (non-root, read-only root filesystem, no capabilities). The Compose file stays the lab path; nothing in it changed.

## 2. Decisions (the PO may revisit)
| Topic | Choice | Why |
| --- | --- | --- |
| Migrations | init container `migrate` of every api pod; `migrations/env.py` takes `pg_advisory_xact_lock` | A Helm pre-install hook runs before the in-chart PostgreSQL exists; a lock makes parallel pods safe (tested with two parallel runs on an empty database) |
| Workers | init container waits for the api `/readyz` | The api is ready only after its migration, so workers never see an old schema |
| Secrets | one generated Secret, kept across upgrades with `lookup`, `resource-policy: keep`; `existingSecret` replaces it | The master key must survive `helm uninstall`/reinstall; `helm template` generates fresh values (no cluster to look up) |
| Connection strings | built into the Secret (`database-url`, `redis-url`) with URL-encoded passwords | Special characters in external passwords; a pod needs no template logic |
| OpenSearch | in-chart: own CA + node certificate (Helm `genCA`, kept in a Secret); internal users hashed by an init container from the Secret passwords | Works with `existingSecret`; no hash in values; same roles as Compose |
| Web → api | nginx template takes `FORGE_API_UPSTREAM` and `FORGE_DNS_RESOLVER` (`auto` = first nameserver of resolv.conf); Compose defaults unchanged | The template had Docker's resolver hardcoded |
| Images | `global.imageRegistry` (default `docker.io`) + repository without host | One value to point everything at a local registry; the air-gap scripts use the same mapping |
| Single replicas for stateful services | PostgreSQL, Valkey, OpenSearch, SeaweedFS, Temporal are one pod each | Same as Compose. HA is by external services; clustering them inside the chart is not planned |
| Metrics | optional PodMonitor (api, workers, port 9100) | Workers have no Service |
| Not in the chart | NetworkPolicies, PodDisruptionBudgets, autoscaling, Langfuse/observability stack | Not in the stories; next if asked |

## 3. Verification (2026-10-22)
- `helm lint` and `helm template` + `kubeconform -strict` for the default values and `ci/external.yaml`, `ci/openshift.yaml`, `ci/existing-secret.yaml` (`make helm/lint`).
- Rendered OpenSearch users script run in the real OpenSearch image: produces a valid `internal_users.yml`.
- Rendered nginx configuration passes `nginx -t` in the web image, with and without the new variables.
- `forge migrate` on an empty database, two processes at once: both succeed, head reached.
- **Not verified:** an installation on a real cluster (none is available on the development host; k3s is installed but stopped and the host is shared and short of memory), OpenShift, the Temporal pod running with `runAsNonRoot` and a read-write root filesystem, `helm test`, and `scripts/airgap-bundle.sh` / `airgap-load.sh` end to end (only the image listing was run). First step when a cluster is at hand: `helm install` with the defaults and `helm test`.
