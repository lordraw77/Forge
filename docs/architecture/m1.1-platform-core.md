# M1.1 Platform core – design

_Roles: Architect, DBA, Security. Stories: [phase-1.md](../requirements/phase-1.md) E1.1–E1.4. ADRs: 002, 003, 006, 007, 011. Date: 2026-10-16._

## 1. Module layout

| Module | Owns | Public interface |
| --- | --- | --- |
| `forge.core.crypto` | AES-256-GCM envelope encryption, HKDF sub-keys from `FORGE_MASTER_KEY` | functions |
| `forge.admin` | secrets store, runtime settings (cache + `LISTEN/NOTIFY`), audit log, bootstrap | `forge.admin.service` |
| `forge.iam` | users, passwords, TOTP, sessions (JWT + refresh), authentication dependencies | `forge.iam.service` |
| `forge.tenancy` | organization, projects, role types, role names, memberships, API keys, permission checks | `forge.tenancy.service` |
| `forge.api` | app factory, router registration, request context | – |

Domain modules import each other only through `service` (import-linter, ADR-001).

## 2. Data model (migration `0002_platform_core`)

| Table | Scope | Key columns | RLS policy |
| --- | --- | --- | --- |
| `organization` | platform | name, settings | none (single row) |
| `app_user` | platform | username, email (unique, case-insensitive), full_name, auth_source, password_hash, is_super_admin, must_change_password, totp_secret_id, totp_enabled, totp_last_step, failed_logins, locked_until, eula_version, status, last_active_at | none |
| `password_history` | platform | user_id, hash | none |
| `recovery_code` | platform | user_id, code_hash, used_at | none |
| `auth_session` | platform | user_id, family_id, refresh_hash, expires_at, idle_expires_at, revoked_at, ip, user_agent | none |
| `role_type` | platform | key, name, permissions[], builtin | none |
| `project` | platform (tenant root) | name, description, status, delete_reason, deleted_at | none; access is via membership |
| `role_name` | project | name, role_type_id, status | standard tenant policy |
| `membership` | project | user_id, role_name_id | read: `project_id = app_project_id() OR user_id = app_user_id()` (a user lists their own projects); write: tenant |
| `api_key` | project | name, prefix (unique), hash, scopes[], expires_at, last_used_at, revoked_at | tenant; lookup by prefix through a `SECURITY DEFINER` function owned by `forge_admin` |
| `secret` | dual | kind, kek_id, wrapped_dek, nonce, ciphertext | dual policy (ADR-002) |
| `setting` / `setting_history` | dual | key, value, version, updated_by | dual policy |
| `audit_event` | dual | actor_id, action, target_type, target_id, diff, ip | read: tenant; insert: `project_id IS NULL OR project_id = app_project_id()`; **no UPDATE/DELETE grant** for `forge_app` |

Notes:

- All ids are UUIDv7, generated by the application.
- `username` and `email` are unique on `lower(...)`.
- `audit_event` is append-only by grants. Platform-wide audit reads (Super Admin console) go through the named `forge_admin` code path.
- The super admin flag is a column, because there is a single organization in the MVP (ADR-003). Project roles are `role_type` → `role_name` → `membership`.
- Default role types are seeded with the ADR-003 permission matrix. Each new project gets one role name per role type: Project Admin, Builder, Operator, User, Viewer.

## 3. Authentication

**Login.** The flow runs in three steps:

1. `POST /api/v1/auth/login` with `{login, password}`. Here `login` is a username or email.
2. If TOTP is enabled, the response is `{"status": "totp_required", "challenge": <signed, 5 min>}`.
3. `POST /api/v1/auth/login/totp` with `{challenge, code | recovery_code}`.

**Session.** On success the server sets two HttpOnly, Secure (configurable for http dev), SameSite=Lax cookies:

| Cookie | Content | Lifetime |
| --- | --- | --- |
| `forge_access` | JWT signed HS256 with an HKDF sub-key of the master key | 10 min |
| `forge_refresh` | Opaque 256-bit token, stored as a SHA-256 hash | Idle 30 min (setting), absolute 12 h |

A readable `forge_csrf` cookie carries the CSRF token.

**Refresh.** `POST /auth/refresh` rotates the refresh token within its family. If an already rotated token is presented again, that is treated as theft: the whole family is revoked and the event is audited.

**CSRF.** Unsafe methods authenticated by cookie require the header `X-CSRF-Token` equal to the `forge_csrf` cookie. API keys (`Authorization: Bearer fk_…`) are never read from cookies and are exempt from CSRF.

**Gates.** A user with any of these flags can reach only `/auth/*` and `/me` until the flag clears; every other route returns `403`:

| Flag | Error code |
| --- | --- |
| Password change required | `password_change_required` |
| EULA not accepted | `eula_required` |
| TOTP enrolment required | `totp_enrollment_required` |

**Brute force.** The defences are:

- 5 failures in 15 min lock the account for 15 min;
- login is limited to 20 requests per minute per IP (Valkey);
- an unknown user still costs one Argon2 verification against a dummy hash;
- the same generic error is returned in every failure case.

**Passwords.**

- Hashed with Argon2id (argon2-cffi defaults: t=3, m=64 MiB, p=4), rehashed when the parameters change.
- Policy: minimum 12 characters (setting), rejected if in the common-password list, no reuse of the last 5.

**TOTP.**

- RFC 6238 with 30 s steps and a ±1 step window. `totp_last_step` rejects reuse of a code.
- The secret is stored in `secret`, encrypted (ADR-006).
- 10 recovery codes, each single-use and stored as a SHA-256 hash.

**Bootstrap.** At API start-up, a transaction takes an advisory lock. If no user exists, it creates `FORGE_ADMIN_*` with `is_super_admin` and `must_change_password`, then audits the creation. If an admin exists and has changed the password while `FORGE_ADMIN_PASSWORD` is still set, start-up logs a warning.

## 4. Authorization

- `Principal` is the authenticated user or API key. It carries user id, super admin flag, and, for API keys, project and scopes.
- `require(permission)` on project routes resolves the membership, then the role name and role type, and checks the permission. For API keys the effective permissions are scopes ∩ the creator's permissions.
- Super Admin routes require `is_super_admin`.
- Foreign or unknown project ids return `404`, never `403` (no existence leak).
- Every request runs DB work in `project_scope(project_id, user_id)` (ADR-002).

## 5. Runtime settings (ADR-007)

- `SettingsService` keeps typed defaults in code (Pydantic models per key), with overrides in `setting`.
- Writes validate, bump the version, write history and audit, and `NOTIFY forge_config` in the same transaction.
- Each process listens on a dedicated asyncpg connection, reloads on notify, and reloads everything on reconnect.
- M1.1 keys:
  - `auth.password_policy`: min_length, history;
  - `auth.lockout`: threshold, window_min, lock_min;
  - `auth.session`: idle_min, absolute_h;
  - `auth.totp_required`;
  - `system.eula`: version, text.

## 6. API surface (M1.1)

| Area | Endpoints |
| --- | --- |
| Auth | `POST /auth/login`, `/auth/login/totp`, `/auth/refresh`, `/auth/logout`, `/auth/password`, `/auth/eula`; `GET /auth/eula`; `POST /auth/totp/enroll`, `/auth/totp/confirm`; `DELETE /auth/totp` |
| Me | `GET /me` (user, flags, permissions per project) |
| Projects (member) | `GET /projects`, `GET /projects/{id}`, members (list, invite, update, remove), role names (list, create, update), API keys (list, create, revoke) |
| Admin (Super Admin) | users (list, create, update, unlock, reset password), projects (list, create, update, archive, delete with reason), audit (query), settings (get, put) |

All routes are under `/api/v1`. Errors are RFC 9457 (ADR-011).

## 7. Threat-model delta

| Threat | Control |
| --- | --- |
| Session theft | HttpOnly cookies, short access JWT, refresh rotation with reuse detection, idle timeout |
| CSRF | Double-submit token on unsafe methods; SameSite=Lax |
| Credential stuffing | Lockout, IP rate limit, Argon2id, generic errors, TOTP |
| TOTP replay | Last-step check |
| Account enumeration | Same error and similar timing for unknown users |
| Privilege escalation | Only Super Admin creates projects and sets `is_super_admin`; project admins cannot grant the platform role |
| Audit tampering | No UPDATE/DELETE grants; diffs redact secrets |
| API key leak | Only prefix and hash stored; shown once; expiry; revoke |
