# M2.6 slice b – Scheduled RAG sources (design)

_Roles: Architect, Engineer, QA. Epic E2.13. Spec: F5 "preconfigured external sources", Data Management. Date: 2026-10-21._

## 1. Model
A **source** feeds one data collection from outside Forge, on a schedule or on demand. The collection, its knowledge bases and its pipelines are unchanged: a synced file is an ordinary document (same ACL, parsing, indexing, citations).

Migration `0018`: `rag_source` (definition, schedule, status), `rag_source_item` (external id → document, version last seen), `rag_source_run` (history, the last 50 per source). All three under forced RLS. Code: `backend/src/forge/rag/sources/` (`connectors.py`, `sync.py`, `activities.py`, `service.py`).

## 2. Sync (`sync.py`)
1. The run lists the source once. An item whose version equals the stored one is **not fetched**.
2. A changed or new item is written to a spooled temp file and goes through the collection's normal upload path, which already skips identical bytes (SHA-256) and re-ingests the rest. Its `(folder, name)` identifies the document, so a changed file replaces its document.
3. **Propagated deletion**: items not listed in this run are deleted from the collection (file, chunks, index entries) when `delete_missing` is on. It is skipped when the listing failed, and **held back** when more than half of the known items would go (or the listing is empty), which usually means an unmounted share or a wrong filter. The run ends `partial` with the reason, and the UI offers *Sync and delete them*.
4. One item failing does not stop the run (`failed`, first 50 errors kept). Unsupported or empty files count as `skipped`.
5. Documents the user deletes by hand are re-fetched on the next run (the item row goes with the document).

## 3. Scheduling (`activities.py`)
- A loop in the **ingest worker** (every 30 s) claims due sources with one `UPDATE … FOR UPDATE SKIP LOCKED` that also moves `next_run_at`, then starts the Temporal workflow `SyncSource` with the id `sync-source-<id>` (conflict policy: use existing). Several workers cannot start the same source twice, and *Sync now* during a run does nothing.
- The sync is one activity (6 h limit, heartbeat per item, no automatic retry; the next run is the retry). A source stuck `running` for 2 h is treated as idle.
- Schedule = an interval in minutes (minimum 5) or manual.

## 4. Connectors (`connectors.py`)
Connectors never touch the database: they get their configuration, decrypted credentials and the project's network policy, and yield items one at a time.

| Type | Reads | Version of an item | Credentials |
| --- | --- | --- | --- |
| `s3` | bucket + prefix, S3-compatible endpoints | ETag + size | `access_key`, `secret_key` |
| `url` | breadth-first crawl of the start URLs' hosts (pages stored as HTML) | hash of the page | `bearer_token` or `headers` |
| `rest` | JSON list (dotted path), optional `next_path` paging; one record = one Markdown/text document | `version_field` + hash | `bearer_token` or `headers` |
| `sql` | one read-only `SELECT` on a project data source, one row = one document (max 1000 rows) | `version_column` + hash | none (the data source's) |
| `git` | shallow clone over HTTPS, files under a sub-path | SHA-256 of the file | `token` or `username`+`password` |
| `filesystem` | a directory under a `FORGE_SOURCE_ROOTS` root bound to the project (mount SMB or NFS there) | mtime + size | none |

Credentials are stored as one encrypted secret (`rag.source`), are write-only in the API (`has_credentials`) and are scrubbed from error messages for Git.

## 5. Security (threat-model delta)
- **SSRF**: every network connector applies the project's egress allowlist (Tools → egress policy) and the private-address rule (`FORGE_TOOLS_ALLOW_PRIVATE_HOSTS`) before connecting; the crawler and REST use the pinned-address client of the HTTP tool. S3 (boto3) and Git (the `git` binary) are checked on the host before the call but resolve the name themselves (a short rebinding window, same as `verify-full` SQL).
- **Filesystem**: off unless the administrator sets `FORGE_SOURCE_ROOTS`. Each root names the projects allowed to read it (`path=<project id>,…;path=*`), so a Builder cannot index a directory meant for another project (found by the security review, 2026-10-21); a root without a project list is ignored. The path is resolved and must sit under a root of the project; symbolic links and files outside the tree are skipped; the API image needs no mount.
- **Git**: HTTPS only, no credentials in the URL (the token is sent as an HTTP header), `GIT_TERMINAL_PROMPT=0`, a scrubbed environment, 10-minute clone limit, the checkout is deleted after the run, `.git` is never read.
- Documents from a source carry the source's ACL (groups/roles chosen on the source).
- Syncs write with the `system` actor; the audit log records source create/update/delete/sync and each document upload and delete.

## 6. API and UI
`/projects/{id}/sources` (list, create, get, patch, delete with `delete_documents`, `types`), `POST …/{id}/sync` (`allow_mass_delete`), `GET …/{id}/runs`. Permission `asset.write` (Builders and Project Admins). UI: Projects Studio → **Sources** (table, form with the configuration as JSON and an example per type, runs dialog with counts and errors).

## 7. Choices to confirm with the PO
1. **Six connector types**, with SMB/NFS served through a mounted directory instead of a native SMB client; a native client (`smbprotocol`) can follow if mounting is not possible.
2. **Interval schedules, not cron**: every N minutes (≥ 5) or manual.
3. **Deletion is on by default** per source, with the 50 % hold-back; *Delete documents too* is a choice when removing a source (default: keep them).
4. **Configuration as JSON** in the form (like guardrail parameters), no per-type forms yet.
5. **The crawler ignores robots.txt** and reads only HTML/text pages of the start URLs' hosts (max 500 pages, depth 5); PDFs linked from a page are not followed (the HTTP client reads text only).
6. **SQL sources are capped at 1000 rows** (the SQL tool's limit); bigger tables need a narrower query or a view.
7. **Sources are not in export/import bundles** (credentials would have to travel), like tools.
8. **A source writes with the `system` actor**; documents show no creator.
9. **Git over HTTPS only**; SSH keys are not supported.
10. **Deployment**: the ingest worker image gains `git` (about 30 MB) and `FORGE_SOURCE_ROOTS` needs the share mounted into that container (Compose volume or PVC).

## 8. Not built
Test connection / dry run before saving, native SMB, SSH Git, webhook-triggered syncs (push), OAuth sources (SharePoint, Google Drive), index maintenance for deleted knowledge bases (see M1.4), page limits for huge PDFs.
