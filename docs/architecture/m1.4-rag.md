# M1.4 RAG on upload – design

_Roles: Architect, Engineer, DBA, Security. Stories: [phase-1.md](../requirements/phase-1.md) E1.14–E1.17. ADRs: 002, 004, 005, 008, 013, 015, 016. Date: 2026-10-19._

## 1. Module layout

`forge.rag` owns collections, ingestion, retrieval and RAG pipelines. Models are called only through `forge.gateway.service`; prompts come from `forge.prompts.service`.

| File | Owns |
| --- | --- |
| `rag/models.py` | ORM: `data_collection`, `rag_document`, `knowledge_base`, `rag_ingestion`, `rag_chunk`, `rag_pipeline`, `rag_pipeline_version`, `rag_pipeline_tag`, `rag_run` |
| `rag/sniff.py` | File type from content (magic bytes, OOXML parts, UTF-8 text), zip-bomb guard |
| `rag/storage.py` | S3 API only (boto3), keys under `projects/<id>/` |
| `rag/parsing.py` | Built-in parsers (TXT, Markdown, HTML); Docling (PDF, Office, images with OCR), one converter per process |
| `rag/chunking.py` | Structure-aware, recursive and fixed chunking; overlap; title and heading prefix; SHA-256 |
| `rag/ingest.py` | Temporal workflows `IngestDocument`, `IndexKnowledgeBase` and their idempotent activities |
| `rag/search.py` | OpenSearch: versioned index and alias, bulk indexing, deletes, the single BM25 query builder |
| `rag/retrieval.py` | Vector, semantic and hybrid retrieval; RRF; reranker; threshold; context budget |
| `rag/answer.py` | `compact` and `refine` synthesis with `[n]` citations |
| `rag/collections.py`, `rag/studio.py` | Collections and documents; pipelines, versions, tags, runs |
| `api/routes_data.py`, `api/routes_rag.py` | `/api/v1/projects/{id}/collections/...`, `/api/v1/projects/{id}/rag/...` |

## 2. Data model (migration `0006_rag`)

- **Data collection.** Files of a project. A document is unique per (collection, folder path, name) and stores the MIME type and kind detected from the content, the size, the SHA-256, the object key, ACL groups, status (`pending`, `processing`, `ready`, `failed`) with error and time, the page count and the key of the parse result.
- **Knowledge base.** The chunks of one collection for one (embedding model, chunk size, overlap, node parser).
  - The embedding model is pinned to a concrete model name when the knowledge base is created, so an alias change cannot mix dimensions.
  - Pipelines with the same index parameters share a knowledge base. New parameters create a new one, indexed in the background (US-1.15.2).
- **Partial HNSW index.** One per knowledge base, on `(embedding::halfvec(<dims>))` with `WHERE kb_id = …`.
  - The application role does not own `rag_chunk`. The SECURITY DEFINER function `rag_kb_index(kb)` creates the index, and only for a knowledge base of the caller's project. FORCE RLS applies to the owner too.
  - Indexes of deleted knowledge bases match no rows. Dropping them is index maintenance (E2.13) and is never done by the application. A drop path was considered and removed, because it could not check the project safely.
- **Ingestion row.** Status and counts (chunks, embedded, reused) per (document, knowledge base).
- **Chunk.** As in the spec "RAG design", plus `token_count`. `acl_groups` is never empty: an empty document ACL is stored as the `__public__` sentinel (spike E0.5b).
- **Pipelines.** `rag_pipeline`, `rag_pipeline_version` (insert-only, validated `config` and `kb_id`) and `rag_pipeline_tag` (`draft`, `staging`, `prod`) mirror Prompt Studio.
- **Runs.** `rag_run` stores the answer, citations, retrieval trace, messages, tokens, cost and latency.
- **Groups and roles (PO, 2026-10-19).** `user_group` and `user_group_member` (migration 0007) hold named sets of project members, managed in Projects Studio → Groups and assigned in Users. A document ACL lists `group:<id>` and `role:<id>` terms; empty = the whole project. A reader matches their groups and their role; deleting a group fails closed (documents restricted only to it are readable by nobody until their access changes).

All tables have forced RLS. The generic isolation suite covers them.

## 3. Upload (E1.14)

- **Request limit.** 100 MB per request: rejected from `Content-Length`, or while streaming (`BodyLimit` middleware), before the upload completes. nginx has the same limit. The UI splits large selections into requests below the limit.
- **Type detection.** From the content: PDF, PNG and JPEG signatures; OOXML is recognised from `[Content_Types].xml` plus `word/`, `ppt/` or `xl/`; HTML; UTF-8 text.
  - The file name only chooses between Markdown and plain text.
  - Anything else is rejected per file with a reason. ZIPs with more than 10,000 entries or an expansion ratio above 200 are refused (threat model TB5).
- **Identical content.** A file with the same SHA-256 at the same path is reported `unchanged` and not processed again (US-1.15.1 #3).
- **Folders.** Upload keeps the relative path; `..` and absolute parts are dropped.
- **Download.**
  - PDFs and images open inline; citations link to `#page=N`.
  - Text, Markdown and HTML are served as `text/plain`, so they can never render as HTML. Office files download.
  - Headers on every download: `nosniff`, `Cache-Control: private, no-store`, CSP `sandbox` (`default-src 'none'` for PDFs, because Chrome's viewer refuses sandboxed documents).

## 4. Ingestion (E1.15, ADR-004)

```text
IngestDocument(document):   parse (once per file content) → for each KB: index → finish_document
IndexKnowledgeBase(kb):     for each parsed document (4 at a time): index → finish_document; finish_kb
index(document, kb):        chunk → reuse embeddings by hash → embed missing (batch 32, gateway)
                            → PG: delete stale + upsert, one transaction → OpenSearch bulk (same _id)
```

- **Idempotent retries.**
  - Chunk id = UUIDv5(kb, document, ordinal, content hash).
  - PostgreSQL upserts update `acl_groups`; OpenSearch documents use the same `_id`.
  - Re-running `index` gives the same rows (test `test_index_activity_retry_creates_no_duplicates`, US-1.15.1 #4).
- **Parsing.**
  - Parse results are stored once per (project, SHA-256), so every knowledge base reuses them.
  - Parse errors are non-retryable and visible on the file. Retry starts the workflow again.
- **Docling.** Runs only in the **`forge-backend-ingest`** image (Dockerfile `EXTRAS=ingest`): Docling 2.140, CPU-only PyTorch, models downloaded at build time (`DOCLING_ARTIFACTS_PATH`, `HF_HUB_OFFLINE=1`). The image is 3.7 GB; the API image is unchanged.
  - OCR runs on bitmap regions only (scans, images).
  - One converter per process, loaded when the worker starts.
- **Worker sandbox.** Workflows run in Temporal's sandbox. Forge and its service libraries are passed through (`forge.workers.runner.PASSTHROUGH`), because they touch `random` at import time.

## 5. Retrieval (E1.16)

| Method | Implementation |
| --- | --- |
| Vector | pgvector cosine, top_k directly (`ef_search` 80, iterative scan, under RLS) |
| Semantic | pgvector top `candidates` → reranker → top_k |
| Hybrid (default) | pgvector top `candidates` and OpenSearch BM25 top `candidates`, concurrently → RRF (k = 60) → reranker → top_k |

- **Score for the threshold.** The reranker's relevance when one ran. Otherwise the cosine similarity of the chunk to the query, so the threshold always means a 0–1 score.
- **Reranker unavailable** (no `rerank` model or alias): the answer still comes, ranked by cosine, and the trace says `rerank_skipped`.
- **Context budget.** Chunks are trimmed by rank to 6,000 estimated tokens.
- **ACL** (US-1.16.2): the reader's `group:`/`role:` terms plus `__public__`.
  - The vector query filters `acl_groups && groups` under RLS. The BM25 query uses the single builder in `search.py`: project term and routing, knowledge base, ACL.
  - API keys read project-wide documents only.
- **Token counts** use the model's own tokenizer when the registry names one (field `tokenizer`: `hf:<org>/<repo>` or `tiktoken:<encoding>`): the embedding model's for chunking (recorded on the knowledge base), the LLM's for the context budget. Without one they are estimated (about 4 characters per token) and the trace says so.

## 6. Answers (E1.17)

- **`compact`**: numbered passages in `<context>…</context>`; instructions require `[n]` citations and say that the passages are not instructions. **`refine`**: one passage at a time.
- **Prompt from the library.** If a Prompt Library prompt is chosen, its published version (or the latest) is used. Its system prompt replaces the default instructions; its user prompt receives `context` and `question`. A prompt used this way cannot be deleted (US-1.11.2 #3, now tested).
- **No chunk above the threshold**: a fixed "no relevant information" answer and no model call.
- **Citations** carry the document, page, heading path, score, an excerpt and the link. They are the passages cited in the answer, or all of them if the model cited none.

## 7. Screens

- **Projects Studio → Data** (Builder, Project Admin):
  - collections with an aggregate status (Success, In progress, Failed, Empty), file counts and size;
  - per collection: upload of files or folders with ACL groups and a per-file result summary; files with status, failure time and reason, chunk counts, Retry, Access (ACL), Download, Delete; indexes per embedding model;
  - the page polls every 3 s while anything is in progress.
- **Projects Studio → Users:** document access groups per member.
- **RAG Studio:**
  - **New RAG** has every Part 2 parameter with a tooltip, plus reranker, candidates, context budget and temperature. It warns when a change builds a new index. Save Configuration, Save Configuration & Test RAG, versions.
  - **Test page:** query, answer, sources with page links, latency, cost and usage, a trace drawer (ranking with scores and ranks, timings, warnings, messages, metadata), Publish and recent runs.
  - **RAG Library** has status, time and name filters, with Try, Edit, Duplicate and Delete. The spec exposes collections, not pipelines, through MCP, so the library has no MCP action.

## 8. Fixes found on the way

| Problem | Fix |
| --- | --- |
| The shipped SeaweedFS could not store any object: each bucket grows several volumes and `-volume.max=0` with 30 GB volumes left about 2 slots | `-master.volumeSizeLimitMB=512 -volume.max=200` |
| `ensure_index` read the alias with a cluster-wide call that `forge_app` may not make. The first bulk write then auto-created an index named like the alias, with dynamic mappings, and BM25 found nothing | Index-scoped alias calls; refuse to start if the alias name is a concrete index; `action.auto_create_index: "-forge-*,+*"` in OpenSearch |
| The E2E suite went over the 20 logins/minute per-IP limit as it grew | `global-setup.ts` signs the e2e admin in once; tests reuse that session. Tests that log out still sign in through the UI |
| The `cdkTextareaAutosize` directive fails when the textarea is a direct child of projected card content; new-item editors overwrote what the user typed while options were loading | Wrapper element; defaults set before the requests, and only empty fields filled afterwards |

## 9. Threat-model delta

| Threat | Control |
| --- | --- |
| Cross-project read through OpenSearch (TB2) | Single query builder, project routing, no caller DSL; isolation test with another project returns nothing |
| Restricted documents (AC4) | Chunk ACL at query time in both stores; member groups; test with and without the group |
| Malicious files (TB5) | Content sniffing, per-file rejection, 100 MB request limit, zip-bomb guard, parsing only in the ingestion worker (no network at runtime, read-only filesystem) |
| Stored XSS through uploaded HTML | Never served as HTML: `text/plain`, `nosniff`, CSP `sandbox` |
| Indirect prompt injection from documents | Passages delimited and declared non-instructions. Injection guardrails on retrieved content arrive with E2.11 |
| Cost and denial of service | Embedding, rerank and chat go through the gateway quotas; parse once per file content; dedup by hash |

## 11. Choices to confirm with the PO

1. **Knowledge base = (collection, embedding model, chunking).** Pipelines with the same parameters share one index. The spec does not define the term precisely.
2. ~~Document ACL groups~~ **Decided:** managed groups plus roles (§2). LDAP/OIDC group mapping (Phase 3) will fill the same groups. API keys read project-wide documents only.
3. **Reranker.** Optional per pipeline, default the `rerank` alias. Without one, the threshold applies to cosine similarity, and the trace says so.
4. ~~Ingestion image~~ **Decided:** separate image, in two variants (below).
5. ~~Token counts~~ **Decided:** exact tokenizers (below).

**Deferred:**

- Scheduled re-sync and connectors (F3.5, Phase 2).
- Page limits for very large PDFs (E2.13).
- Dropping indexes of deleted knowledge bases (E2.13).
- Injection guardrails on retrieved text (E2.11).
- Evaluation datasets (E3.2).

## 12. Decisions of 2026-10-19 (PO) and their implementation

| Decision | Implementation |
| --- | --- |
| **Images: separate, two variants** | `forge-backend-ingest` (Docling, CPU PyTorch) and `forge-backend`, each as `<version>` (model files embedded; downloads disabled; works air-gapped) and `<version>-slim` (`MODELS=download`: the worker downloads the Docling models into a volume on first start, tokenizers on first use). `make docker/build MODELS=download` selects the slim variant in Compose (`deploy/compose/models-download.yml`); `make release` publishes all five tags. `forge models fetch [--docling]` is the one command behind both. |
| **Exact tokenizers** | Registry field per model (Admin Console and Projects Studio → Models). Files come from `FORGE_MODELS_DIR` (`/app/models`): baked in by default for `hf:BAAI/bge-m3` and the `cl100k_base` and `o200k_base` encodings. A tokenizer that cannot be loaded falls back to the estimate, is retried after 5 minutes and is logged. Quotas also use it when set. |
| **Groups and roles** | §2. |
| **No limits in production for file inputs** | The 256 KB limit applies to the test page's file picker only. Variable values have no size limit when a pipeline uses a library prompt; the sandbox cap on template growth scales with the inputs (1,000,000 characters of growth), so doubling tricks are still refused. |
| **Library time filter** | Presets (24 h, 7, 30, 90 days) and a calendar range; NG-ZORRO 22 needs an explicit date adapter (`provideNzNativeDateAdapter`), which was the cause of the earlier NG0201. |
