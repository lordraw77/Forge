# ADR-016 – BM25 full-text search in OpenSearch

- Status: Accepted (PO, 2026-10-18)
- Date: 2026-10-18
- Supersedes: the pg_search parts of [ADR-008](008-vector-and-fulltext.md). Vector search stays in PostgreSQL.
- Amends: [ADR-002](002-tenancy-rls.md), the rule for BM25 queries.

## Context

ADR-008 put BM25 in PostgreSQL with ParadeDB's `pg_search`, which is AGPL-3.0. The PO did not accept AGPL for Forge's distribution, and chose an external search engine over the alternatives (analysis question 8, 2026-10-18).

| Option | Licence | Why not chosen |
| --- | --- | --- |
| pg_search (ParadeDB) | AGPL-3.0 | Licence |
| VectorChord-bm25 | AGPL-3.0 | Licence |
| pg_textsearch (Tiger Data) | PostgreSQL | Young (v1.0 in April 2026); no documented way to keep project, KB and ACL filters inside the top-k scan |
| Native PostgreSQL FTS | PostgreSQL | No real BM25; ranks every match. Stays as a fallback behind the retriever interface |
| Meilisearch, Typesense | MIT (CE), GPL-3.0 | Ranking is not BM25 and less tunable for RAG; Typesense would need a licence exception |
| **OpenSearch** | **Apache-2.0** | **Chosen** |

OpenSearch was chosen because:

- it has real, configurable BM25 and language analyzers, including Italian;
- it filters in the bool filter context, which is cached;
- it is mature and runs air-gapped.

## Decision

- **Split by store.**
  - **PostgreSQL** remains the **system of record**: `rag_chunk` keeps content, metadata, ACL and embeddings. HNSW search and RLS are unchanged (ADR-008).
  - **OpenSearch** holds a **derived, rebuildable index** for BM25 only.
- **Index layout.**
  - One shared index per schema version, `forge-chunks-v<N>`, behind the alias `forge-chunks`.
  - Routing is by `project_id`, with `_routing` required.
  - The mapping is strict: `project_id`, `kb_id`, `document_id`, `acl_groups` as `keyword`; `content` and `heading_path` as `text`; `page`.
  - Analyzers are chosen per knowledge-base language: the `content` field plus language subfields.
  - Re-indexing creates the next version, then swaps the alias.
- **Tenant isolation without RLS.**
  - Every query is built by **one function** in `forge.rag`. It always adds `project_id` (term plus routing), `kb_id` and `acl_groups` (terms, with the `__public__` sentinel from E0.5b) as filters.
  - Free-form query DSL from callers is never accepted.
  - An isolation test runs in CI (as in spike E0.5e).
- **Consistency.**
  - Chunks are indexed by the ingestion workflow (Temporal activity, E1.15) after the PostgreSQL commit, with `_id = rag_chunk.id`, so retries are idempotent.
  - Deletes and ACL changes are written to PostgreSQL first and propagated by the same workflow.
  - A reconcile job compares counts and per-document hashes and re-indexes on drift (E2.13).
  - Retrieval reads from PostgreSQL; OpenSearch returns only ids and scores.
- **Hybrid retrieval.**
  - The vector top 40 (PostgreSQL) and the BM25 top 40 (OpenSearch) run concurrently.
  - RRF (k = 60) is computed in the retriever.
  - Queries use `track_total_hits: false` and `_source: false`, which keeps the top-k scan.
- **Security.**
  - The OpenSearch security plugin is on, with TLS on HTTP and transport. Certificates come from a deployment CA generated by `scripts/gen-env.sh` in Compose and a cert-manager issuer in Helm; demo certificates are never used.
  - Forge connects as the user `forge` with role `forge_app`: `forge-*` indices only, no cluster administration.
  - The connection settings are infrastructure wiring (ADR-007): `FORGE_SEARCH_URL`, `FORGE_SEARCH_USERNAME`, `FORGE_SEARCH_PASSWORD`, `FORGE_SEARCH_CA_FILE`.
- **Images.**
  - PostgreSQL moves from the ParadeDB image to `pgvector/pgvector` (PostgreSQL 17, trixie). `scripts/db-from-paradedb.sh` upgrades existing volumes.
  - OpenSearch runs as the Compose service `search` (`opensearchproject/opensearch`), single node, `node.store.allow_mmap: false`, so the host's `vm.max_map_count` does not need changing.
- **Readiness.** `/readyz` includes `search`.

## Consequences

- Licences: the whole stack is permissive (Apache-2.0, PostgreSQL, MIT).
- About 1.5 GB more RAM with a 1 GB heap. One more service to back up; its index can always be rebuilt from PostgreSQL.
- Isolation for BM25 now depends on Forge code, not on the database: a single query builder, code review and the CI isolation test (threat model TB2).
- ADR-002's BM25 exception (no literal `project_id`) no longer applies; OpenSearch queries always carry it.
- Measured in spike E0.5e ([report](../spikes/e05e-opensearch-bm25.md)).
