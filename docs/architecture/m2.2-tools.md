# M2.2 Tools Studio – design

_Roles: Architect, Engineer, DBA, Security, QA. Stories: [phase-2.md](../requirements/phase-2.md) E2.2. ADRs: 001, 004, 006, 011. Date: 2026-10-19._

Scope: HTTP tools, OpenAPI import, MCP client (Streamable HTTP, SSE, stdio), read-only SQL, credentials, egress policy, test console, call log, library tools in agents. Connectors (E2.3) are low priority (PO) and not included.

## 1. Module layout

`forge.tools` owns the library. Agents use it only through `forge.tools.service`; the shared outbound HTTP guard moved from `forge.agents.egress` to `forge.core.egress`.

| File | Owns |
| --- | --- |
| `tools/models.py` | ORM: `tool`, `tool_version`, `credential`, `datasource`, `mcp_server`, `tool_policy`, `tool_call` |
| `tools/schemas.py` | Tool definitions (`http`, `sql`, `mcp`), credentials, policy, data sources, MCP servers, call log, OpenAPI import |
| `tools/runtime.py` | Executors, argument validation (JSON Schema 2020-12), secret scrubbing |
| `tools/sqlguard.py` | Literal-aware scanner: one SELECT/WITH, `:name` → `$n`, forbidden words |
| `tools/openapi.py` | OpenAPI 3.x import (local `$ref` only) |
| `tools/service.py` | `ToolStudio`, `PreparedTool` |
| `core/egress.py` | Host allowlist, public-address check, address pinning, redirects, caps (`request`, `fetch`) |
| `api/routes_tools.py` | REST under `/projects/{id}` |

## 2. Data model (migration `0011_tools`)

All tables have `project_id` and forced RLS. `tool_version` is insert-only; a tool has `latest_version` and `published_version` (no tags: a tool is either published at one version or not). Secrets (credential values, data source passwords) are rows of the `secret` table with the project id (AES-256-GCM envelope, ADR-006). `tool_call` is the call log (input and output bounded to 64 KB).

## 3. Execution

1. `ToolStudio.prepare` resolves a tool version for one run: policy hosts, the credential or password in plain text (in memory only), the data source, the MCP server.
2. `PreparedTool.execute` validates the arguments against the stored schema (unknown arguments refused), runs the executor, and **scrubs** every known secret value from the content, the output and the request before they are returned or stored. An API that echoes `Authorization` cannot put the token in the model's context, the run view or the log.
3. HTTP: the URL template takes path values URL-encoded; query, header and JSON body come from the parameters; the credential is added last (Bearer, Basic, header, query). The request shown to people masks it. Redirects are followed for GET/HEAD only and drop `Authorization`/`Cookie` when the host changes.
4. SQL: `$n` placeholders (values bound, never concatenated); `BEGIN READ ONLY`, `SET LOCAL statement_timeout`, a cursor that fetches `row_limit + 1` rows. The scanner rejects comments, dollar quotes, several statements and writing keywords; the read-only transaction is the real barrier.
5. MCP: a session per call (`mcp.Client`), with the tool's timeout. The URL goes through the egress policy; `stdio` runs only executables listed in `FORGE_MCP_STDIO_ALLOWED`. Results are text blocks inside `<untrusted-content>`.
6. Every call is written to `tool_call` (test console and agents), including refused ones.

**Agents.** `AgentConfig.tools` accepts `{"kind": "library", "tool_id", "version?", "name?"}`; saving the agent version pins the published tool version (an unpublished tool is refused). The runtime prepares library tools at the start of a run; a tool that cannot be prepared (deleted, credential removed) becomes a tool that returns an error. Tool names are unique in the agent. A tool with `requires_approval` returns `approval_not_available` until M2.4. Deleting a tool used by an agent version (latest or tagged) is refused, naming the agents.

## 4. Choices to confirm with the PO

1. **Egress policy per project** (Project Admin) plus one deployment flag `FORGE_TOOLS_ALLOW_PRIVATE_HOSTS` for internal APIs. Private addresses are refused by default, which makes internal systems (Jira on-prem, Zabbix) need that flag for the whole installation. A per-project "allow private" switch would need a Super Admin approval step; not built.
2. **MCP tools are flagged "can change data"** (the server cannot tell us), and HTTP tools with a non-GET method likewise. The flag is informational until HITL.
3. **MCP stdio** is off by default and limited to named executables, because it starts a process inside the worker. Strong isolation (sandbox service) is E3.4.
4. **SQL**: PostgreSQL only; for `verify-full` the connection resolves the name again (a short DNS-rebinding window). Other databases come later.
5. Tools are not yet part of export/import bundles (ADR-018): the next change adds `tool` items by name, without credentials.
6. MCP responses of type image/resource are shown as `[image]`, not passed on.

## 5. Threat-model delta (TB4)

| STRIDE | Threat | Control |
| --- | --- | --- |
| E | SSRF through HTTP tools, MCP URLs and data sources | Per-project host allowlist (empty = nothing); public addresses only unless the deployment flag; connection pinned to the checked address (HTTP); redirects re-checked and followed for GET only; size and time caps; refused calls are logged |
| I | Credentials in responses, logs, audit or run steps | Stored encrypted per project; never returned; masked in the request view; **scrubbed from results** even when the remote echoes them; audit stores names only; tests inspect each place and the database |
| I | Credential sent to another host after a redirect | `Authorization`/`Cookie` dropped when the host changes |
| T | SQL injection / writes through a SQL tool | Values bound as parameters; scanner rejects anything but one SELECT/WITH; read-only transaction; statement timeout; row cap; project admin controls the data source |
| E | A model-supplied argument changes the request in unplanned ways | Arguments validated against the saved schema, unknown ones refused; path values URL-encoded; headers and body only from declared parameters |
| E | Prompt injection through tool results | Results inside `<untrusted-content>` with a data note; clipped; `requires_approval` and HITL in M2.4 |
| E | Command execution through MCP stdio | Disabled by default; only executables in `FORGE_MCP_STDIO_ALLOWED` |
| R | Who called what | `tool_call` log with user, run, tool version and status |
| D | A slow or huge response | Timeouts 1–60 s per tool, 256 KB body cap, response clipping |
