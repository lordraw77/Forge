# M1.3 Prompt Studio – design

_Roles: Architect, Engineer, Security. Stories: [phase-1.md](../requirements/phase-1.md) E1.10–E1.13. ADRs: 002, 005, 011, 012. Date: 2026-10-18._

## 1. Module layout

`forge.prompts` owns prompts and their executions. It calls models only through `forge.gateway.service` (ADR-001, ADR-005).

| File | Owns |
| --- | --- |
| `prompts/models.py` | ORM: `prompt`, `prompt_version`, `prompt_tag`, `prompt_run` |
| `prompts/schemas.py` | Inputs and outputs: spec Part 2 "Prompt fields", runs and traces |
| `prompts/templates.py` | `{name}` shorthand, sandboxed Jinja2, resource budgets, variable detection |
| `prompts/studio.py` | `PromptStudio`: library, versions, tags, test, playground, Help Me Write |
| `prompts/assist.py` | Help Me Write meta-prompt, frameworks, tolerant JSON parsing |
| `prompts/service.py` | Public interface |
| `api/routes_prompts.py` | `/api/v1/projects/{project_id}/prompts/...` |

Gateway change: `GatewayResponse.info` (`CallInfo`) now carries the recorded `llm_call` id, model, tokens, cost and latency for non-streaming chats, so internal callers can show a trace without querying `llm_call`.

## 2. Data model (migration `0005_prompt_studio`)

| Table | Key columns | Notes |
| --- | --- | --- |
| `prompt` | name (unique per project, case-insensitive), description, latest_version | Name and description are not versioned |
| `prompt_version` | prompt_id, version, model (alias or model name), system_template, user_template, variables, examples, model_params, note | **Insert-only**: `UPDATE`, `DELETE` and `TRUNCATE` are revoked from `forge_app` and `forge_admin`. Rows go away only through the cascade from `prompt`, because referential actions run as the table owner |
| `prompt_tag` | (prompt_id, tag) → version; tag ∈ `draft`, `staging`, `prod` | FK to (prompt_id, version) |
| `prompt_run` | kind (`test`, `playground`, `assist`), group_id, model requested and used, status, error, variables, rendered messages, params, output, tokens, cost, latency, cache_hit, llm_call_id | Trace store. `UPDATE` is revoked |

All four tables have forced RLS with the tenant policy. The generic isolation suite covers them.

**Tags and status (US-1.10.2, US-1.11.2):**

- Every save creates the next version and moves `draft` to it.
- **Publish** moves `prod` to a chosen version, the latest by default.
- A prompt is **Published** while it has a `prod` tag. Otherwise it is **Draft**.
- `staging` is set by hand.
- `staging` and `prod` can be removed. Removing `prod` unpublishes the prompt.
- Agents (E1.18) will pin `name@version` or follow a tag.

## 3. Templates and the sandbox

**Syntax.**

- The spec writes variables as `{name}`. The renderer rewrites `{name}` to `{{ name }}`, for an identifier inside single braces only, so JSON such as `{"a": 1}` is left alone.
- Full Jinja2 also works: `{{ name|upper }}`, `{% if %}`, `{% for %}`.

**Variables.**

- Variables are detected from both templates, in order of appearance, system prompt first.
- Detected variables the editor did not declare are added on save as required variables.
- The editor mirrors this detection while the user types (`variables.ts`). The server remains authoritative (`POST /prompts/parse`).

**Execution order:** system prompt → few-shot examples as user/assistant pairs (literal, not rendered) → rendered user prompt.

**Sandbox.** Templates come from builders and are treated as hostile. Threat model TB5: "Jinja2 template injection".

| Control | Detail |
| --- | --- |
| Environment | `ImmutableSandboxedEnvironment`, no loader, autoescape off (the output is text sent to a model) |
| Statements | `macro`, `call`, `import`, `from`, `include`, `extends`, `block`, `filter`, `with` refused at parse time |
| Names | Globals: only `range` (at most 1,000 items) and `dict`. No `lipsum`, `cycler`, `joiner` or `namespace` |
| Attributes | Any `_*` attribute raises, also on undefined values. Callable attributes only from a method allowlist (`items`, `get`, `lower`, `split`, …). `str.format` is blocked |
| Filters | Allowlist. No `center`, `indent`, `batch`, `slice`, `format`, `pprint` or `random`. `replace` checks its result size first |
| Operators | `*`, `**` and `+` are intercepted: string and list results ≤ 1,000,000 characters, integers ≤ 4,096 bits, exponent ≤ 64 |
| Budget | A per-thread trace on the compiled template: at most 200,000 line steps, 1 s, and no local value above the size cap after any line. This stops doubling loops and nested loops |
| Limits | Template ≤ 32,000 characters; variable value ≤ 262,144 characters; output ≤ 1,000,000 characters |

- Rendering runs in a worker thread (`asyncio.to_thread`).
- Compiled templates are cached by source text (LRU, 256 entries): versions are immutable.
- 28 known injection and exhaustion payloads are unit-tested (`test_sandbox_blocks_known_payloads`, US-1.10.1 #4). The API test also checks that a hostile template is refused at render time with `422 template_render_failed`.

## 4. Runs and traces (US-1.11.1, US-1.12.1)

- **Test** renders the chosen version (the latest by default) with the given values over the declared defaults.
  - Missing required variables return `422 missing_variables`; unknown names return `422 unknown_variables`.
  - The model is the version's model unless the request overrides it.
- **Playground** renders once, then calls 2–4 distinct models concurrently. Each run is stored with the same `group_id`.
- **Model failures are failed runs, not HTTP errors.** The run stores `error_code` and the message (for example `upstream_unavailable`), so one failing model never hides the others.
- **The trace** is `GET /prompts/runs/{run_id}`: latency, cost, usage, the rendered input messages, the output and metadata (params, variables, finish reason, cache hit, model requested and used, `llm_call_id`). The gateway's `llm_call.trace_id` is `prompt_run:<id>`, so both records link to each other.
- `prompt_run` is the M1.3 trace store. E1.20 (run/step persistence, OTel spans) will absorb it.

## 5. Help Me Write (US-1.13.1)

- It calls the project's `default-chat` alias with a meta-prompt, at temperature 0.4. The call is traced as an `assist` run.
- The user's description is wrapped in `<description>` tags and treated as data.
- The model must answer with JSON: `framework`, `system_prompt`, `user_prompt`. The parser accepts code fences and surrounding prose. If the JSON cannot be used, the response is `502 assist_invalid_output`, with the run id for the trace.
- **Frameworks:** Free Form (the default), CO-STAR, RISEN, RTF and CRISPE, each with a tooltip.
  - The spec says "default Free Form" and also "if no framework is chosen, the system recommends one". Both hold: Free Form sends no framework, the model picks the best fit, and the result names it ("Recommended framework used: …").
  - An explicit choice is always honoured.

## 6. API surface (ADR-011)

Every endpoint needs `asset.write` (Project Admin, Builder; spec role matrix). Writes and runs also need a writable project (`409 project_archived`).

| Method and path (under `/api/v1/projects/{project_id}/prompts`) | Purpose |
| --- | --- |
| `GET ""` `?status=&q=&since=&until=&cursor=&limit=` | Library: cursor pagination (updated_at, id), LIKE wildcards escaped |
| `POST ""` | Create: name, description (required, "asked on first save"), first version |
| `GET/PATCH/DELETE /{id}` | Latest version with tags; rename or edit description; delete with reference check |
| `POST /{id}/duplicate` | New prompt from the latest version, with a new name |
| `GET /{id}/versions`, `GET /{id}/versions/{n}`, `POST /{id}/versions` | History; one version; save = new version |
| `POST /{id}/publish`, `PUT/DELETE /{id}/tags/{staging,prod}` | Tags |
| `POST /{id}/test`, `POST /{id}/playground`, `GET /{id}/runs`, `GET /runs/{run_id}` | Runs and traces |
| `POST /parse`, `POST /assist` | Live validation; Help Me Write |

Errors: `name_taken` (409), `template_invalid` (422, with field, line and message per issue), `version_not_found` (404), `prompt_in_use` (409, with the references), `invalid_cursor` (400), and the gateway's resolution errors on save (`model_not_found`, `model_not_enabled`, `wrong_model_type`).

## 7. Screens

**Prompt Studio** has the tabs **New Prompt** and **Prompt Library** and follows the "New" and "Library" page patterns of the spec.

**Editor:**

- the name is edited inline;
- the model dropdown lists aliases and models;
- system and user prompt, each with a tooltip; Help Me Write sits next to the user prompt;
- variables table with Name, Value, Is File Input and Is Required, plus Add Variables; a variable that is no longer used in the prompt is marked;
- examples; temperature and max tokens; a version note;
- template errors are shown with their line number;
- **Save** and **Save & Test Prompt**; on first save the description dialog opens;
- a version drawer shows read-only versions with "Load into editor".

**Test page:**

- version selector; inputs (file inputs read a text file up to 256 KB in the browser); Proceed is disabled until the required variables are filled;
- the result shows output, latency, cost, total usage and model, with the trace in a drawer;
- Publish;
- **Compare models** runs 2–4 models side by side;
- a list of recent runs.

**Library:**

- filters: status, time range (any time, 24 hours, 7, 30 or 90 days) and name search; Load more;
- the row menu has Try, Edit, Duplicate (asks for a name) and Delete (asks for confirmation). Add to MCP Servers is disabled until Phase 3.

**Deviation from ADR-012:** the template fields are monospace textareas, not Monaco. Monaco would add about 3 MB, and its web workers need CSP changes. Revisit in Phase 2 with the agent studio editors.

## 8. Threat-model delta

| Threat | Control |
| --- | --- |
| Template injection / sandbox escape (TB5) | §3 controls; payload suite in CI |
| Denial of service through rendering | Step, time and size budgets; worker thread; cached compilation |
| Cost abuse through test runs | Runs go through the gateway: quotas, rate limits and the `max_tokens` ceiling apply (M1.2) |
| Cross-project access | RLS on all four tables; ids from other projects return 404 (tested) |
| Tampering with history | Versions are insert-only at the database privilege level (tested) |
| Prompt injection into Help Me Write | The description is delimited as data. The output is only a suggestion, inserted by the user and never executed |
| Sensitive data in traces | Traces stay in the project's database under RLS. Export to external sinks follows ADR-009 (content off by default) |
